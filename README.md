# Student CRUD – Micronaut (beginner friendly)

A small REST API built with **Micronaut 4** that can **C**reate, **R**ead, **U**pdate and **D**elete students.
It is designed to be easy to read and a good first project for learning Micronaut.

## Features
- Full CRUD for students, plus search by name
- Input validation (`@NotBlank`, `@Email`, `@Min`)
- Layered design: Controller → Service → Repository
- **PostgreSQL first, H2 fallback**: if PostgreSQL is not running, the app starts on an in-memory H2 database automatically
- Integration tests with `@MicronautTest`
- Ready-made Postman collection

## Tech stack
| Area | Technology |
|---|---|
| Language | Java 17+ |
| Framework | Micronaut 4.7 |
| Data access | Micronaut Data (JPA / Hibernate) |
| Databases | PostgreSQL (primary), H2 (fallback and tests) |
| Build tool | Maven |

## Prerequisites
- JDK 17 or 21 (check with `java -version`)
- Maven 3.8+ (check with `mvn -v`)
- PostgreSQL (optional; without it the app uses H2)

## Project structure
```text
src/main/java/com/example
├── Application.java                   # starts the app, chooses PostgreSQL or H2
├── model/Student.java                 # the data (database table)
├── repository/StudentRepository.java  # talks to the DB (implementation is auto-generated)
├── service/StudentService.java        # business logic between controller and DB
└── controller/StudentController.java  # the REST endpoints
src/main/resources
├── application.yml                    # common config + PostgreSQL settings
└── application-h2.yml                 # H2 settings, used only for the fallback
```

**Request flow:** HTTP request → Controller → Service → Repository → Database

## Database setup

### Option A: PostgreSQL (default)
Create the database and user once:

```sql
CREATE USER student WITH PASSWORD 'student';
CREATE DATABASE student_crud OWNER student;
```

Default connection settings:

| Setting | Default | Environment variable |
|---|---|---|
| URL | `jdbc:postgresql://localhost:5432/student_crud` | `JDBC_URL` |
| Username | `student` | `JDBC_USER` |
| Password | `student` | `JDBC_PASSWORD` |

Hibernate creates the `student` table automatically (`hbm2ddl.auto: update`).

### Option B: H2 (no install needed)
Do nothing. If PostgreSQL cannot be reached, the app switches to the `h2` environment and loads `application-h2.yml`.
Look for one of these lines in the console at startup:

```text
>>> PostgreSQL is available. Using PostgreSQL.
>>> PostgreSQL is NOT available. Falling back to H2 in-memory database.
```

> **Note:** H2 is in-memory, so data is lost when the app stops.
> A wrong PostgreSQL password also triggers the fallback. Check the `PostgreSQL check failed` message in the console for the real reason.

## Run the app
```bash
mvn clean mn:run
```
The app starts at **http://localhost:8080**.

## API endpoints
| Operation | Method | URL | Success status |
|---|---|---|---|
| Create | `POST` | `/students` | `201 Created` |
| Read all | `GET` | `/students` | `200 OK` |
| Search by name | `GET` | `/students/search?name=Ash` | `200 OK` |
| Read one | `GET` | `/students/{id}` | `200 OK` (`404` if not found) |
| Update | `PUT` | `/students/{id}` | `200 OK` (`404` if not found) |
| Delete | `DELETE` | `/students/{id}` | `204 No Content` (`404` if not found) |

### Student JSON
```json
{
  "name": "Asha",
  "email": "asha@example.com",
  "age": 21
}
```

| Field | Rules |
|---|---|
| `name` | required, not blank |
| `email` | required, must be a valid email |
| `age` | at least 1 |
| `id` | generated by the database; do not send it when creating |

### Example response (`201 Created`)
```json
{
  "id": 1,
  "name": "Asha",
  "email": "asha@example.com",
  "age": 21
}
```

## Try it

### With Postman
Import `student-crud.postman_collection.json`. Run **Create Student** first; it saves the new id into the `studentId` variable used by the other requests.

### With curl (macOS / Linux / Git Bash)
```bash
# Create
curl -X POST localhost:8080/students -H "Content-Type: application/json" \
  -d '{"name":"Asha","email":"asha@example.com","age":21}'

# Read all
curl localhost:8080/students

# Read one
curl localhost:8080/students/1

# Search by name
curl "localhost:8080/students/search?name=Ash"

# Update
curl -X PUT localhost:8080/students/1 -H "Content-Type: application/json" \
  -d '{"name":"Asha K","email":"asha@example.com","age":22}'

# Delete
curl -X DELETE localhost:8080/students/1
```

### With PowerShell (Windows)
`curl` in PowerShell is an alias for another command, so use `Invoke-RestMethod`:
```powershell
# Create
Invoke-RestMethod -Method Post -Uri http://localhost:8080/students `
  -ContentType "application/json" `
  -Body '{"name":"Asha","email":"asha@example.com","age":21}'

# Read all
Invoke-RestMethod http://localhost:8080/students

# Delete
Invoke-RestMethod -Method Delete -Uri http://localhost:8080/students/1
```

## Validation demo
```bash
curl -i -X POST localhost:8080/students -H "Content-Type: application/json" \
  -d '{"name":"","email":"bad","age":0}'
```
Returns `400 Bad Request` with a message for each invalid field.

## Troubleshooting
| Problem | Likely cause and fix |
|---|---|
| `Connection to localhost:5432 refused` | PostgreSQL is not running. Start it, or let the app fall back to H2 (see *Database setup*). |
| `No backing RepositoryOperations configured for repository` | Missing `micronaut-data-hibernate-jpa` / datasource config, or a stale build. Run `mvn clean mn:run`. |
| `The argument does not represent an annotation type: Entity` | `micronaut-data-hibernate-jpa` is missing from `pom.xml`, or `Student` imports `Entity` from the wrong package. Use `jakarta.persistence.*`. |
| Build errors on very new JDKs | Use JDK 17 or 21 and set `JAVA_HOME` to it. |
| Port 8080 already in use | Stop the other app, or run with `MICRONAUT_SERVER_PORT=8081`. |
